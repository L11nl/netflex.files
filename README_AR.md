# Generator Email — الموقع + بوت تيليجرام الكامل على Railway

هذا الإصدار يشغّل **الموقع + API + بوت تيليجرام** داخل نفس خدمة Railway ونفس عملية Node.js.

## وظائف البوت
- إنشاء إيميل عشوائي قصير على `@5xu.vn`.
- إنشاء إيميل يدوي: أرسل الاسم فقط مثل `nabil77` أو العنوان كاملاً `nabil77@5xu.vn`.
- حفظ عدة إيميلات لكل مستخدم.
- كل إيميل يحتوي على 5 بروفايلات مرتبة من 1 إلى 5.
- الرموز الافتراضية للبروفايلات: `1212`، `1001`، `2121`، `2026`، `2002`.
- تغيير رمز أي بروفايل من داخل البوت.
- حالات البروفايل: متاح / قيد المراجعة / تم البيع.
- عند بيع البروفايلات الخمسة ينتقل الإيميل إلى قسم الإيميلات المباعة.
- نسخ الإيميل والرمز من الأزرار عندما يدعم إصدار Telegram زر `copy_text`.
- فحص الرسائل يدوياً لأي إيميل محفوظ.
- **مراقبة تلقائية** لكل الإيميلات المحفوظة: عند ظهور رسالة جديدة يرسلها البوت إلى تيليجرام تلقائياً مع الأكواد والروابط.
- استخراج أكواد التحقق ذات 4 أرقام والروابط الموجودة داخل الرسائل.
- حذف الإيميل من **بيانات البوت** وإيقاف مراقبته تلقائياً بعد 6 أيام من إضافته.
- حذف الإيميل يدوياً قبل انتهاء المدة.
- اسم محلي اختياري لكل إيميل.

> ملاحظة: حذف الإيميل بعد 6 أيام يعني حذفه من بيانات البوت وإيقاف مراقبته. Generator.email لا يوفر هنا API موثوقاً لحذف صندوق البريد نفسه من خوادمه.

## الموقع
الموقع يبقى يعمل من مجلد `public/`، وقراءة Generator.email تتم من السيرفر عبر:

`GET /api/inbox?email=example@5xu.vn`

لذلك لا يعتمد على CORS من المتصفح.

## متغيرات Railway
### مطلوب
`TELEGRAM_BOT_TOKEN=ضع_توكن_البوت_الجديد_هنا`

لا تضع التوكن داخل `server.js` ولا ترفعه إلى GitHub.

### اختيارية
`PUBLIC_URL=https://YOUR-PROJECT.up.railway.app`

`TELEGRAM_ALLOWED_IDS=123456789,987654321`
- إذا تركته فارغاً يستطيع الجميع استخدام البوت.
- إذا وضعته، يعمل فقط مع Telegram IDs الموجودة بالقائمة.

`AUTO_CHECK_INTERVAL_MS=30000`
- مدة فحص البريد التلقائي بالميلي ثانية.
- الافتراضي 30 ثانية.
- أقل قيمة داخل المشروع 15 ثانية لتقليل الضغط على خدمة البريد.

`BOT_STATE_FILE=/data/bot-state.json`
- هذا هو المسار المفضل للحفظ الدائم.

## مهم جداً: Railway Volume
حتى تبقى الإيميلات والبروفايلات والرموز وحالة الرسائل محفوظة بعد إعادة Deploy أو Restart:

1. افتح مشروع Railway.
2. أضف **Volume** للخدمة.
3. اجعل Mount Path هو:

`/data`

4. أضف Variable:

`BOT_STATE_FILE=/data/bot-state.json`

بدون Volume قد تضيع بيانات البوت عند إعادة إنشاء الحاوية.

## النشر
1. ارفع الملفات إلى GitHub بأسمائها الأصلية.
2. يجب أن يكون الملف الرئيسي `server.js`.
3. يجب أن يكون ملف الموقع `public/app.js`.
4. Deploy من GitHub إلى Railway.
5. أضف `TELEGRAM_BOT_TOKEN`.
6. أنشئ Public Domain من Networking.
7. يفضّل جداً إضافة Volume على `/data`.
8. افتح:

`https://YOUR-DOMAIN/health`

سترى شيئاً قريباً من:

```json
{
  "ok": true,
  "telegram": {
    "configured": true,
    "status": "running",
    "autoCheckSeconds": 30,
    "storedChats": 1
  }
}
```

## ملاحظة عن الموقع والبوت
الموقع والبوت يستعملان **نفس خدمة Railway ونفس قارئ البريد**. حالياً بيانات الموقع الشخصية تحفظ في LocalStorage داخل المتصفح، بينما بيانات البوت تحفظ في `bot-state.json`. لذلك لا يتم دمج سجلات المتصفح مع سجلات تيليجرام تلقائياً.
